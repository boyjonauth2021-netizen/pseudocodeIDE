1. Composite vs non-composite

Non-composite data type: a type that holds a single value. Built-in examples include INTEGER, REAL, BOOLEAN, CHAR, STRING and DATE. User-defined non-composite types are enumerated and pointer types.
Composite data type: a type that holds a set of values under one name. User-defined composite types include record, set and class / object. An array is also composite (several values of the same base type).
Kind In Chapter 13.1
Non-composite (user-defined) Enumerated type · Pointer type
Composite (user-defined) Record · Set · Class / object
Also composite Array (1D / 2D; often of records)

Why user-defined types? A programmer may need a type that does not already exist in the language; to represent a particular group of data under one identifier; to extend existing types; to make code easier to read; or to match the program’s requirements exactly.

2. Non-composite user-defined types

2.1 Enumerated type

Enumerated type: a user-defined non-composite type whose possible values are a fixed list of identifiers (no quotes). The list defines an order, so values can be compared and you can move with + 1 / - 1. Useful when a field has a small, fixed set of allowed values (for example taxi codes or seasons).

Runnable in the online IDE

TYPE Season = (Spring, Summer, Autumn, Winter)
DECLARE ThisSeason : Season
DECLARE NextSeason : Season
ThisSeason ← Spring
NextSeason ← ThisSeason + 1
IF ThisSeason = Spring THEN
  OUTPUT "Start of year"
ENDIF
OUTPUT ThisSeason
OUTPUT NextSeason
IF NextSeason > ThisSeason THEN
  OUTPUT "Later season"
ENDIF

Expected output: Start of year, Spring, Summer, Later season

2.2 Pointer type

Pointer type: a user-defined non-composite type whose value is the address (location) of another variable. Purpose: to refer indirectly to data — used with linked lists and trees. ^Variable takes the address (referencing); Pointer^ reads or writes the value at that address (dereferencing).

Runnable in the online IDE

TYPE TIntPointer = ^INTEGER
DECLARE Counter : INTEGER
DECLARE MyPointer : TIntPointer
DECLARE Result : INTEGER
Counter ← 42
MyPointer ← ^Counter
Result ← MyPointer^
OUTPUT Result
MyPointer^ ← 100
OUTPUT Counter

Expected output: 42 then 100

3. Composite types

3.1 Array (1D)

Array: a composite type storing several values of the same base type, each accessed by an index. Bounds are written as ARRAY[low:high] OF Type.

Runnable in the online IDE

DECLARE Marks : ARRAY[1:5] OF INTEGER
DECLARE Index : INTEGER
DECLARE Sum : INTEGER
Marks[1] ← 12
Marks[2] ← 15
Marks[3] ← 9
Marks[4] ← 18
Marks[5] ← 11
Sum ← 0
FOR Index ← 1 TO 5
  Sum ← Sum + Marks[Index]
NEXT Index
OUTPUT Sum
OUTPUT Marks[4]

Expected output: 65 then 18

3.2 Array (2D)

Two-dimensional array: a table of values of the same type, accessed with two indices (row, column).

Runnable in the online IDE

DECLARE Grid : ARRAY[1:2,1:3] OF INTEGER
DECLARE R : INTEGER
DECLARE C : INTEGER
DECLARE Total : INTEGER
FOR R ← 1 TO 2
  FOR C ← 1 TO 3
    Grid[R,C] ← R * 10 + C
  NEXT C
NEXT R
Total ← 0
FOR R ← 1 TO 2
  FOR C ← 1 TO 3
    Total ← Total + Grid[R,C]
  NEXT C
NEXT R
OUTPUT Grid[2,3]
OUTPUT Total

Expected output: 23 then 102

3.3 Record

Record: a composite user-defined type that groups several fields, which may have different data types, under one type name. Declared with TYPE … ENDTYPE. Fields are accessed with a dot: Booking1.ClientName.

Runnable in the online IDE

TYPE Student
  DECLARE StudentID : STRING
  DECLARE FullName : STRING
  DECLARE Mark : INTEGER
  DECLARE Passed : BOOLEAN
ENDTYPE

DECLARE S1 : Student
S1.StudentID ← "S001"
S1.FullName ← "Maya Chen"
S1.Mark ← 72
S1.Passed ← S1.Mark >= 50
OUTPUT S1.StudentID
OUTPUT S1.FullName
OUTPUT S1.Mark
IF S1.Passed THEN
  OUTPUT "Passed"
ENDIF

Expected output: S001, Maya Chen, 72, Passed

3.4 Array of records

Array of records: each element of the array is a whole record. Useful for tables of entities (fleet of vehicles, list of bookings).

Runnable in the online IDE

TYPE Product
  DECLARE ProductCode : STRING
  DECLARE UnitPrice : REAL
ENDTYPE

DECLARE Catalogue : ARRAY[1:3] OF Product
DECLARE Item : Product
DECLARE I : INTEGER
Item.ProductCode ← "P10"
Item.UnitPrice ← 2.50
Catalogue[1] ← Item
Item.ProductCode ← "P20"
Item.UnitPrice ← 4.00
Catalogue[2] ← Item
Item.ProductCode ← "P30"
Item.UnitPrice ← 1.25
Catalogue[3] ← Item
FOR I ← 1 TO 3
  OUTPUT Catalogue[I].ProductCode
  OUTPUT Catalogue[I].UnitPrice
NEXT I

Expected output: P10, 2.5, P20, 4, P30, 1.25

3.5 Set

Set: a composite user-defined collection of values of one base type. Order is not significant and values should not be repeated. Declare the set type with TYPE Name = SET OF BaseType, create a set with DEFINE, test membership with IN, and combine sets with UNION, INTERSECTION, DIFFERENCE.

Runnable in the online IDE

TYPE LetterSet = SET OF CHAR
DEFINE Vowels ('A', 'E', 'I', 'O', 'U') : LetterSet
DEFINE Soft ('A', 'E', 'O') : LetterSet
DEFINE Digits ('0', '1', '2') : LetterSet
DECLARE Combined : LetterSet
DECLARE Shared : LetterSet
DECLARE OnlyVowels : LetterSet

IF 'E' IN Vowels THEN
  OUTPUT "E is a vowel"
ENDIF

Combined ← Vowels UNION Digits
Shared ← Vowels INTERSECTION Soft
OnlyVowels ← Vowels DIFFERENCE Soft

OUTPUT Combined
OUTPUT Shared
OUTPUT OnlyVowels

Expected output: E is a vowel, then {A, E, I, O, U, 0, 1, 2}, {A, E, O}, {I, U}

3.6 Class / object (theory only)

Class: a composite user-defined type used in object-oriented design. It groups attributes (data) and methods (operations). An object is an instance of a class. Exam questions often ask for set and class / object as the other composite user-defined types besides record.
Not runnable in this IDE yet. Written answers may use CLASS / PRIVATE / PUBLIC / ENDCLASS. For live practice here, model data fields with a record (section 3.3). 
// Theory illustration only — do not run in the IDE
CLASS Patient

  PRIVATE DateSeen : DATE

    // constructor would assign attributes
  ENDPROCEDURE
ENDCLASS

4. Combined exam-style example

Typical Paper 3 pattern: declare an enumerated type, then a composite record that includes that type and a DATE field.

Runnable in the online IDE

TYPE Vehicle = (M100, M230, T101, T102, T120, T150)

TYPE Booking
  DECLARE BookingNumber : STRING
  DECLARE Destination : STRING
  DECLARE ClientName : STRING
  DECLARE ClientTelephone : STRING
  DECLARE DateOfDeparture : DATE
  DECLARE PickupAddress : STRING
  DECLARE TaxiUsed : Vehicle
ENDTYPE

DECLARE Booking1 : Booking
Booking1.BookingNumber ← "B204"
Booking1.Destination ← "Airport"
Booking1.ClientName ← "Sam Lee"
Booking1.ClientTelephone ← "57155060"
Booking1.DateOfDeparture ← "22/11/2026"
Booking1.PickupAddress ← "12 Ring Road"
Booking1.TaxiUsed ← T101

OUTPUT Booking1.BookingNumber
OUTPUT Booking1.ClientName
OUTPUT Booking1.DateOfDeparture
OUTPUT Booking1.TaxiUsed
IF Booking1.TaxiUsed = T101 THEN
  OUTPUT "Taxi T101 assigned"
ENDIF

Expected output: B204, Sam Lee, 22/11/2026, T101, Taxi T101 assigned
